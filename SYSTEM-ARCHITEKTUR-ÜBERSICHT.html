🔄 DATENFLUSS

User-Authentifizierung

``` User → Token generieren → HMAC-SHA256 → API → Verifikation → Thinker-ID → Presence Update ```

Verschlüsselung

``` User-Key → PBKDF2 → AES-Key → AES-256-GCM → Verschlüsseltes Modul → Manifest → Signatur (Ed25519) ```

Entschlüsselung

``` User-Key → PBKDF2 → AES-Key → Manifest laden → Signatur prüfen → AES-256-GCM → Entschlüsseltes Modul ```

Transfer-Prozess

``` User → Transfer-Formular → API → Datenbank → Status Update → Response ``` ---

🔐 SICHERHEITS-ARCHITEKTUR

Verschlüsselungs-Ebenen

``` Layer 1: User-Key (Input) ↓ Layer 2: PBKDF2 Key Derivation (200.000 Iterationen) ↓ Layer 3: AES-256-GCM Verschlüsselung ↓ Layer 4: Ed25519 Signatur (Producer) ↓ Layer 5: Manifest (Metadaten + Signatur) ```

Authentifizierungs-Ebenen

``` Layer 1: Token-Generierung (localStorage) ↓ Layer 2: HMAC-SHA256 Signatur ↓ Layer 3: API-Verifikation ↓ Layer 4: Thinker-ID-Generierung ↓ Layer 5: Presence-Update ``` ---
